# Hosting on Cloudflare Workers static assets

Since October 2026 gamedev.trebeljahr.com is a static export served by the
Cloudflare Worker `gamedev`. There is no Worker script and no app server. The
asset bytes (models, sprites, audio, download objects) stay on R2 at
assets.gamedev.trebeljahr.com, unchanged.

## How a request is answered

- The zone route `gamedev.trebeljahr.com/*` sends the hostname to the Worker.
  A second route, `gamedev.trebeljahr.com/.well-known/acme-challenge/*` with no
  Worker, keeps that path on the origin while Traefik on the old Coolify host
  still holds a certificate. Delete it when the Coolify app is retired.
- `wrangler.jsonc` has `assets` only: no `main`, no `routes`, no `cache`,
  `workers_dev: false`. With no script, every request is an asset request,
  and asset requests do not count toward the 100,000 requests/day of Workers
  Free. Adding `main`, `run_worker_first` or `cache.enabled` changes that.
  Leaving out `routes` keeps `wrangler deploy` from touching the API-made
  routes.
- `html_handling: auto-trailing-slash`: `/kaykit` serves `kaykit.html`;
  `/kaykit/` redirects (307) to `/kaykit`.
- `not_found_handling: 404-page`: unknown paths answer 404 with `404.html`.
- `showcase/public/_headers`: `no-store` for `/version.json` and
  `/release-assets.json`, `image/png` for the extensionless social images.
  Everything else gets Cloudflare's default
  `public, max-age=0, must-revalidate` with an ETag. Do not add a long-lived
  rule for `/_next/static/*`: `_headers` also applies to 404s, so a missing
  chunk would be cached for a year.
- `out/_redirects` is generated by `showcase/scripts/build-static-site.ts`.
  `_redirects` runs before asset matching and cannot match a query string.

## What the build writes (showcase/scripts/build-static-site.ts)

`pnpm build` runs `next build` (`output: "export"`) and then this script, which:

- overwrites `out/manifest.json` and `out/media-catalog.json` with the
  license-filtered catalogs. The raw files in `public/` list packs production
  must not show. The old server applied the same filter in route handlers.
- deletes the per-pack files of restricted art packs.
- writes `/api/catalog.json` (the whole agent catalog in one response, see
  `docs/catalog-api.md`) and `/api/catalog.schema.json`.
- writes `/api/media/art-json/<folder>.json` (a pack with resolved sample URLs).
- writes `/api/downloads/<vendor>/<pack>.json`: model file → immutable
  download object. Download links fetch their pack's map when they render.
- writes `/api/models/download.html`, which forwards old
  `/api/models/download?file=…` links in the browser.
- writes `_redirects`: one 307 per pack ZIP to its object on R2, 200 proxies
  for `/api/models/manifest`, `/api/media/catalog`,
  `/api/media/catalog/packs/:file`, `/api/media/art/*`, and every
  `/media/2d/:pack/:asset` page to the single page at `/media/2d/item`.
- keeps only the `.html` of the 7,000+ model pages and drops their RSC payload
  and segment files, so links to model pages are plain document navigations.
- fails when the upload passes 18,000 files (Workers Free allows 20,000 per
  version; the rest is room for carried chunks) or a file passes 25 MiB.

## Deploys (.github/workflows/deploy.yml)

1. Build: export, then `scripts/carry-static.mjs` downloads the hashed
   `/_next/static/` files of the two previous releases from the live site
   (listed in `/release-assets.json`) and adds them to `out/`. A Worker version
   serves only its own files; without the carry, a tab opened before a deploy
   404s its chunks about 70 s later. The script is a copy of hatchkit's
   `cli/src/templates/client-host/scripts/carry-static.mjs`.
2. `wrangler versions upload --tag <sha>`. Nothing is live yet. (A Worker
   that was never deployed refuses `versions upload`; the job then uses
   `wrangler deploy`, which only happens before the route exists.)
3. Deploy job, when `GAMEDEV_WORKER_MODE=automatic` or on a `deploy` dispatch:
   `wrangler versions deploy <version>@100%`, then
   `scripts/verify-release.mjs` waits until `/version.json` and the homepage
   `build-commit` meta name the commit for 16 samples in a row. Uploading
   first and activating later avoids the seconds of 404s on new chunks that a
   one-step `wrangler deploy` leaves.

CI holds `CLOUDFLARE_API_TOKEN` (a token for this one Worker, role
"Individual Workers Editor", minted by `hatchkit secrets isolate`) and
`CLOUDFLARE_ACCOUNT_ID`. It cannot change routes, DNS or other Workers.

## Rollback

- A bad release: dispatch the workflow with `operation: rollback` and the
  version id from `pnpm exec wrangler versions list`, or run
  `pnpm exec wrangler versions deploy <id>@100%` with the token. A version
  keeps its own files, so the rollback is complete within seconds.
- The whole move, while the Coolify app still runs: delete the route
  `gamedev.trebeljahr.com/*`. The Coolify container answers again within
  about 8 s.

## Local preview

`pnpm build` (with `NEXT_PUBLIC_ASSETS_BASE_URL` set), then `pnpm preview`
serves `showcase/out` on workerd exactly as uploaded, `_redirects` and
`_headers` included. Assets from R2 fail CORS on localhost; R2 allows only
the production origin.
